# Crest 0.3.0 PRD implementation

The 24 November 2026 implementation adds a supported initial scope for every remaining F19–F26 catalogue entry to the existing P0/P1/P2 application. The owner selected local and free defaults. All optional sources start disabled and use the existing island controller. None can reveal Crest on a background event.

Open **Settings → Integrations** to configure a source. Enabling the first source adds **Optional integrations** to the island dock. **Settings → Modules** can hide that dock entry independently. Sources can be turned off individually; their panels provide clear or disconnect controls.

| Requirement | Implemented scope | Limits |
| --- | --- | --- |
| F19 notifications | Windows `UserNotificationListener`, explicit Settings permission request, app previews, optional titles/bodies, per-item acknowledgement and clear. Memory only, 50 items, bounded text, 24-hour expiry. | Windows must grant access. Portable/ordinary installer packages may lack the required identity/capability; optional MSIX packaging declares it. No replies or changes to Windows notification banners. Capability/package acceptance remains open. |
| F20 weather | Explicit city search through Open-Meteo; temperature, conditions and wind; 30-minute cache, last refresh, stale/offline feedback and cache clear. | Sends selected city/search and coordinates to Open-Meteo when enabled. No continuous location access. Free public service availability and usage terms apply. |
| F21 calendar | Explicit local `.ics` file, up to 200 events over 90 days, timezones and all-day dates, common daily/weekly/monthly/yearly recurrence, exceptions and overrides. Details hidden by default. | Read-only; no account access or event modification. Complex unsupported recurrence/timezone rules are reported and skipped. Source file stays untouched. |
| F22 accessory batteries | On-request reads of standard Bluetooth LE battery services on connected paired accessories; name, reported percentage or explicit unavailable state and last-read time. | No inferred battery values. Proprietary/classic Bluetooth devices may expose no standard value. Physical accessory verification remains open. |
| F23 meeting integration | Teams, Zoom and Google Meet join links from calendar events, with exact provider/URL validation and explicit launch. | Join through the named app/browser. No universal microphone, mute or hang-up automation is advertised. |
| F24 downloads | Only Crest-owned HTTP(S) transfers to a chosen new filename; known/unknown-length progress, two-transfer concurrency, cancel, retry, remove and clear; partial-file cleanup. | Four GiB per transfer; no monitoring of other apps. Existing destination files are never overwritten. Files remain in chosen folders after list removal. |
| F25 AI | Opt-in read-only conversation with an existing loopback Ollama service and selected installed model; bounded requests/responses/context, cancel, clear, disconnect. | No bundled model; local model installation is separate. No tools, execution, file/clipboard access or remote account. Only typed conversation is sent to the selected local service. |
| F26 phone integration | Capability check and explicit handoff to installed Microsoft Phone Link. Pairing and calls/messages remain in Phone Link. | Crest reads no phone account or messages. Supported operations depend on Phone Link, Windows and the chosen phone. No iPhone parity or in-island phone controls are claimed. |

The PRD deliberately requires named, individually specified P3 adapters. These scopes implement that initial catalogue; broader account calendars, meeting mute controls and direct phone-data access need an additional integration specification. Crest 0.3.0 remains a prerelease candidate while package, device, accessibility, display and measured performance acceptance are incomplete.

Two local requirements were completed too: disabling Controls stops system-counter sampling, and retained clipboard history now uses Windows DPAPI for the current user. Enabled legacy plaintext history migrates immediately; protection failure removes retained plaintext and keeps only session data with an explanation. Truncated clipboard entries are identified without splitting Unicode surrogate pairs. Existing retention preferences are preserved.

## Compatibility and retained data

The core controls require no account, model, key or online connection. Weather and owned downloads use the network only after their source is enabled and the user requests the operation. Calendar reads the explicitly selected local file. AI requires an existing local Ollama service and an installed model; Crest does not download or start a model. The model's CPU, memory and possible download costs belong to that separately installed service.

| Source | Data retained by Crest | Turning off, clearing or disconnecting |
| --- | --- | --- |
| Clipboard | At most 100 entries, 8,192 characters per entry and 120,000 characters overall; persisted text is protected for the current Windows user. Existing 1–30-day unpinned retention remains configurable. | Off and clear remove pins and ordinary history. Pause retains existing history with expiry still active. Unreadable protected data is cleared with recovery feedback. |
| Notifications | Memory only: up to 50 previews, 8,192 body characters per item and 120,000 combined characters. Titles and bodies are hidden by default. Items expire after 24 hours. | Acknowledge/clear affect Crest's copies. Off, disconnect and quit remove retained previews; Windows' own notifications and banners remain controlled by Windows. |
| Weather | One selected-city weather snapshot in local `weather.json`; chosen city and coordinates are preferences. The provider receives city search text and selected coordinates. | Clear removes the snapshot; off removes cached weather. Disconnect also removes the selected city and coordinates. |
| Calendar and meeting joins | The chosen `.ics` path remains a preference. Up to 200 parsed events over 90 days remain in memory; details are hidden by default. | Clear removes parsed events; disconnect also removes the source reference. Original calendar files are untouched. Explicit joins send the chosen meeting URL to its app/browser. |
| Accessory battery | At most 16 paired BLE device names/IDs, reported values and read times in memory after refresh. No continuing battery polling. | Disconnect, clear and quit remove the readings. Device pairing and permission stay in Windows. |
| Owned downloads | At most 20 task references/progress records in memory; two active transfers, each up to four GiB. A completed file remains in its explicitly chosen destination. | Cancel/off/clear stop Crest transfers and clean partial files. Removing or clearing the task list leaves completed files in place. Tasks are not resumed automatically after quit. |
| Local AI | Typed conversation only, in memory: 4,000 characters per prompt, bounded answers, at most 12 messages and 60,000 conversation characters. Requests go to the selected loopback service. | Clear, off, endpoint/model changes, disconnect and quit remove conversation and cancel obsolete work. No file, clipboard, system-data, command or external-action tools are supplied. |
| Phone Link | Only capability status; no phone account, messages or access tokens are retained by Crest. | Off/disconnect remove the handoff state. Pairing, privacy and supported calls/messages remain in Microsoft Phone Link. |

These initial adapters store no online account credentials or access tokens. Routine diagnostics exclude notification text, calendar details, clipboard text, prompts and credentials. Optional-source failures leave the local controls usable and cannot reveal the island.

The ordinary installer and portable package are unpackaged desktop distributions. F19 requires Windows to accept a package identity with the `userNotificationListener` capability and then grant the explicit Settings request. The optional MSIX manifest provides the declared identity/capability path; creating an installable package additionally needs Windows SDK tools and a valid existing publisher signature trusted by Windows. A manifest or successful compile alone does not verify notification access. BLE readings and Phone Link handoff similarly depend on actual Windows/device support.

## Verification and distribution

Domain fixtures exercise permission defaults, bounded storage, weather cache/offline states, calendar recurrence and joins, download cancellation/no-overwrite/cleanup, AI loopback-only requests and late-result rejection, and actual Windows DPAPI round trips. WPF probes use isolated synthetic data and render the new panels in light and dark themes. The native clipboard listener suite can be omitted explicitly with `--skip-native-clipboard`; omitted checks are recorded, never counted as passed.

The previous 0.2.1 owner acceptance and gate records remain historical for their recorded binary in [release-gates-0.2.1.json](release-gates-0.2.1.json). This changed source does not inherit those results. The current [release-gates.json](release-gates.json) holds 31 pending technical rows and no inherited owner approval. It has not been installed over the owner's paused instance, and no Windows permissions, pairing, model installation or trust settings were changed during implementation.

Build with the pinned SDK as described in [BUILD.md](BUILD.md). Optional identity packaging uses [package-msix.ps1](../scripts/package-msix.ps1) and [AppxManifest.xml](../installer/AppxManifest.xml), requiring Windows SDK MakeAppx and an explicitly selected signing certificate for installable output. It does not create/trust a certificate or install the package. Normal self-contained portable and installer workflows remain available.

The implementation snapshot passed 139 domain outcomes, 147 WPF/UI outcomes against its exact packaged DLL, 11 release-provenance checks, 16 evidence-verification checks, 10 geometry checks and three observer-lifecycle checks. Its self-contained candidate started hidden and exited with code 0 in an isolated profile. Eleven native clipboard-writing outcomes were explicitly omitted. Twelve new light/dark panel renders were generated and inspected. [prd-completion-verification.json](prd-completion-verification.json) preserves that snapshot's artifact identity and limits. Release-pipeline changes require their own final source-bound package verification. Physical notification access, accessory/phone operation, full screen-reader and display acceptance, frame timing and clean-account installation remain separate compatibility checks.
